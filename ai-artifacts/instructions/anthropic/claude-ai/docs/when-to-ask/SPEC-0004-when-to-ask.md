# SPEC-0004: When to ask

## Goal

Reversible work proceeds without a question; costly work waits for an answer;
and every question arrives with enough context that Dennis can answer it in
one line.

## Scope

- In: whether to ask, when to ask, and the shape of the question.
- Out: where the question is recorded - SPEC-0001.

## Acceptance

- A low-risk, easily undone change is made without asking.
- Work that is hard to verify, costly to undo, or built on a guessed fact is
  asked about before it starts.
- A non-obvious question carries its tradeoffs, a recommendation with
  reasoning, and a closed ask for confirmation - never an open one.
- Assumptions are stated; inferences are labelled as inferences and kept
  apart from what Dennis said.
- Where several interpretations exist they are presented, not picked silently.

## Constraints

- A rename is cheap; a file layout, an ID scheme, or a name already in
  someone else's hands is not. The second kind is what Dennis spends attention
  on.
- Answering a question is not the same as deciding; a question about an item
  leaves it open.
